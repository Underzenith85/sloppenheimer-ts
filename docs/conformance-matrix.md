# Symphony SPEC conformance matrix

This matrix targets Sections 17 and 18 of the upstream Symphony SPEC, Draft v1, as retrieved on
2026-08-29. It was re-verified against that revision and this working tree on 2026-09-01, once every
issue raised by the 2026-08-30 audit — [#66](https://github.com/Underzenith85/sloppenheimer-ts/issues/66), [#67](https://github.com/Underzenith85/sloppenheimer-ts/issues/67), [#68](https://github.com/Underzenith85/sloppenheimer-ts/issues/68), [#69](https://github.com/Underzenith85/sloppenheimer-ts/issues/69),
[#70](https://github.com/Underzenith85/sloppenheimer-ts/issues/70), [#71](https://github.com/Underzenith85/sloppenheimer-ts/issues/71), [#72](https://github.com/Underzenith85/sloppenheimer-ts/issues/72) and [#73](https://github.com/Underzenith85/sloppenheimer-ts/issues/73) — had reached a recorded decision.

`pnpm test:conformance` is deterministic and needs no network or credentials. The default
`pnpm test` includes both core and extension conformance and explicitly excludes
`test/real-integration`. Run the opt-in profile with `pnpm test:real-integration`.

A row states a met requirement unless it is marked **Deviation**, **Known limit**, **Extension** or
**Disposition**. SPEC 15.1 and the Normative Language section's implementation-defined clause both
require that the selected behaviour be documented; the index below plus the detailed rows it points
at are that record, so a reader can tell a met requirement from a deliberate departure without
reading the code.

([#167](https://github.com/Underzenith85/sloppenheimer-ts/issues/167)). Nothing below reads the
agent's account of what it did: the worktree against its recorded baseline, the published commit
and the expected remote head are the evidence.
